# Trust Model

Who and what may control which decisions, stated directly.

## Untrusted or partially trusted

None of the following may ever decide ALLOW/BLOCK, calculate authoritative
impact, or bypass a check:

- the natural-language instruction
- the agent-selected tool
- the agent-selected business arguments (`inactive_days`, `environment`,
  `flag_name`, `enabled`, `rollout_percentage`, ...)
- MCP client input (validated, but still untrusted until validated)
- model-generated semantic extraction (Nebius intent/risk features)
- model-generated tool proposals (`agent/agent_proposal.py`)
- model-generated repair proposals (`agent/agent_repair.py`)
- model explanations / natural-language rationale
- client-supplied proof identifiers or claims (`RollbackProof` as handed
  to the gateway -- every field is re-validated against server-side
  metadata, never trusted as given)

## Trusted deterministic components

These are the only things that may decide, calculate, or record:

- the tool registry (`proofgate/registry.py`)
- selector canonicalization and hashing (`proofgate/selector.py`)
- impact adapters (`operations/actions.py`, `operations/feature_flags.py`)
- policy rules (`proofgate/policy.py`)
- server-side proof metadata (`operations/snapshots.py`'s stored metadata,
  looked up by `snapshot_id`)
- proof validation (`proofgate/proofs.py`)
- workflow budget (`proofgate/budgets.py`)
- governed dispatch (`proofgate/core.py::guarded_execute`)
- the Operations boundary (mutation functions themselves)
- postcondition verification (`proofgate/postcondition.py`)
- rollback eligibility and resolution (`proofgate/rollback.py`)
- restoration and its independent verification
  (`operations/restoration.py`, `proofgate/rollback.py`)
- audit append logic (`proofgate/audit.py`)

## Trusted local demo fixtures

Data the deterministic code treats as ground truth for this local
sandbox:

- SQLite seed data (`operations/pristine.db`, generated by
  `operations/seed.py`)
- feature-flag audience data (`operations/feature_flag_audience.json`)
- pristine feature-flag configuration
  (`operations/feature_flags_pristine.json`)
- snapshots created by trusted server-side code (`operations/snapshots.py::
  create_snapshot`) -- never a snapshot path or ID supplied by a caller
  and trusted without a metadata lookup

## Never accepted as authorization

Stated directly, because these are the exact things a naive design might
mistakenly trust:

- agent confidence (a model's own stated certainty)
- model prose or explanations
- suggested repairs (`suggested_repairs` is advisory only; it never
  affects a verdict, and the repair path always re-runs full policy
  evaluation on the repaired request)
- transcript narrative (anything printed or written to a demo transcript
  is a record of what happened, never an input to what is allowed to
  happen)
- caller-provided impact counts (impact is always recomputed by
  deterministic preview code, never accepted from the caller)
- arbitrary snapshot paths (restoration only ever targets a snapshot
  looked up by ID from trusted metadata, never a caller-supplied path)
- arbitrary database paths (`operations/restoration.py::restore_snapshot`
  has no destination parameter at all -- it can only ever write to
  `operations/working.db`)
- caller-provided budget values (`WorkflowBudget` state lives entirely in
  server-side process memory, keyed by `workflow_id`; nothing in a
  request can set or override it)
- model claims that proof is valid ("the recovery proof is valid" stated
  by a model or in an explanation string is never checked -- validity is
  only ever determined by `proofgate/proofs.py::validate_rollback_proof`
  cross-checking every field against stored server-side metadata)
